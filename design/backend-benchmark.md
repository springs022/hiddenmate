# 候補世界バックエンド ベンチマーク

## 目的

明示列挙型と再生型について、初期化時間、探索時間、プロセスのピークワーキングセットを比較し、Web・CLIの既定バックエンドを判断する。

## 測定条件

- 測定日: 2026-08-31
- OS: Windows 10 x86_64
- Rust: 1.98.0、releaseビルド
- 各ケースを独立プロセスで9回実行し、中央値を採用
- メモリはWindows `GetProcessMemoryInfo`の`PeakWorkingSetSize`
- ベンチマーク実行ファイル: `hiddenmate_core/examples/backend_benchmark.rs`

ピークワーキングセットにはRustランタイムなどの基礎使用量も含まれる。ブラウザWasmの実測値ではないため、絶対値ではなく同一環境での方式間比較として扱う。

## シナリオ

| シナリオ | 内容 | 候補世界 | 探索 |
|---|---|---:|---:|
| `variable2-1ply` | 持駒の覆面駒2枚、各7駒種候補 | 49 | 1手、最大100解 |
| `variable6-init` | 盤上の覆面駒6枚、各4駒種候補 | 4,039 | 初期化のみ |
| `invisible1-5ply` | 攻方透明香1枚 | 71 | 5手、最大2解 |
| `invisible2-1ply` | 攻方透明香1枚、受方透明飛1枚 | 5,610 | 1手、最大1解 |

| シナリオ | 方式 | 初期化 | 探索 | ピークメモリ |
|---|---|---:|---:|---:|
| `variable2-1ply` | 明示列挙 | 0.255 ms | 12.541 ms | 3.555 MiB |
|  | 再生 | 0.221 ms | 29.587 ms | 3.512 MiB |
| `variable6-init` | 明示列挙 | 9.279 ms | ― | 5.238 MiB |
|  | 再生 | 8.215 ms | ― | 3.203 MiB |
| `invisible1-5ply` | 明示列挙 | 0.819 ms | 5.342 ms | 3.910 MiB |

## 評価

- 再生型の初期化は、候補世界を保持しないため同等または約46%まで短縮された。
- 数千世界では、再生型がピークメモリを約2.0～2.3 MiB、約32～39%削減した。
- 探索時間は再生型が約2.4倍～13.8倍になった。履歴を初形から繰り返し再生するコストが支配的である。
- 透明駒2枚・5,610世界でも、初期化と探索の合計は明示列挙約118 ms、再生型約196 msで、再生型が約1.7倍遅い。
- 71世界の5手探索ではメモリ差が測定誤差内なのに対し、再生型は合計で約12倍遅い。

## 結論

現段階では明示列挙型をWeb・CLIの既定として維持する。再生型は、候補世界が多くメモリ制約を優先する場合の実験用バックエンドとして残す。

単純な候補世界数だけで自動的に再生型へ切り替えるのもまだ適切ではない。5,610世界のケースでもメモリ削減は2.3 MiBに対して探索時間が約4倍になったためである。既定化または自動選択の前に、次の改善を検討する。

1. 履歴途中のチェックポイントを一定間隔で保持する。
2. 観測着手ごとの遷移結果または制約差分を共有する。
3. 再生する初形部分集合をビット集合で索引付けする。
4. ブラウザWasmで時間と`WebAssembly.Memory`使用量を測定する。
