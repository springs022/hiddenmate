## 0. なぜ既存資産がそのまま使えるか

| 項目 | 双玉40枚（達成済） | 単玉39枚（本挑戦） |
|---|---|---|
| コマンド | `single-king-smoke ideal-backward --double-king` | 同（`--double-king` を**外すだけ**） |
| 理論上限 | 40 | **39**（`theoretical_max_piece_count` が算出、テスト済） |
| 詰上がり | 玉 + 攻方玉 + 攻方1枚 = 3枚 | 玉 + **攻方2枚** = 3枚 |
| 玉以外の駒数 | 38 | **38**（同じ） |
| 必要な最小手数 | 2×(40−3)=74手 | 2×(39−3)=**72手** |
| 歩の比率 | 18/38 = 47.4% | 18/38 = 47.4%（同じ） |

**要点:** 「玉以外の38枚を盤に載せる」という一番きつい部分は双玉40枚と**まったく同数**で、
必要手数はむしろ2手短い。`--min-pawn-pct 44` などの 44 regime の制約もそのまま整合する
（と金は歩として数えられる: `board_pawn_count` は ProPawn を含む）。

単玉モードは元々このコマンドの既定であり（コマンド名 `single-king-smoke` がその名残）、
逆算・一意性厳密検証・beam・checkpoint・合流解析などの機構は**すべて単玉でも動く**。

### 双玉との質的な違い（見積りの不確実性）

- **失うもの:** 攻方玉。詰上がりの多様性が減る（双玉に切り替えた当初の動機がこれ）。
  攻方玉は取られない・自由に動ける駒として逆算の自由度を与えていた。
- **得るもの:** 詰上がりの攻方駒が1枚→**2枚**になるので、終端局面の種類自体は増える
  （実測: 44 regime で canonical **4541 群**の3枚詰上がりが列挙される）。
  また攻方の手数（選択肢）が減るぶん、一意性は保ちやすい可能性がある。
- どちらが効くかは事前には決められない。**実測で決める**（§2）。

## 1. 手法（双玉40枚で確立したレシピ）

1. **逆算BFS + 一意性の厳密検証**（`BackwardSearch`）
   3枚の詰上がりから1手ずつ遡り、各候補について「協力手順がちょうど1本」を
   深さ制限DFS（memo付き）で完全探索により判定する。beam を使っても
   **一意性の判定は近似しない**ので、見つかった局面は本物。
2. **制約 regime で探索空間を絞る**
   `--min-pawn-pct 44`（歩比率下限）、`--rook-bishop-allow-start 31`、
   `--lance-knight-allow-start 8`、`--goldish-priority`。
   これらは探索 step ではなく**局面内在の駒数**で効くので、途中局面を seed に
   据え直しても同じ意味で効く。
3. **学習誘導 beam**
   85次元の特徴量 → GBDT で「そこから到達できる最大駒数」を予測し、
   温度サンプリング（Gumbel-top-K, T≈15）と駒数 bucket の stratify を併用して選別。
   `--beam-sota` で学習済みモデルを一発指定できる。

   **単玉への転用可能性（`analysis/smoke_cone/FEATURE_IMPORTANCE.md` から）:**
   - SOTA モデル（300木・85特徴）の分岐に使われた特徴の上位45個に、**攻方玉に固有の特徴は
     一つも入っていない**。`board_black_king` は学習データ上で定数（常に1枚）だったため
     **一度も分岐に使われていない**（同 §2.1 (b)）。したがって単玉（＝この特徴が常に0）でも
     モデルの木構造が壊れることはない。
   - 効いているのは駒数・位相を除くと **F 玉の自由度 27%／D 玉の位置と包囲 26%／
     G 配置の散らばり 25%** の3群（`king_escape_depth`, `king_centroid_cheby`,
     `king_white_neighbors_attacked`, `total_black_kiki`, `king_flight_cov_avg`,
     `king_ray_freedom`, `row_std`, `hand_white_total` など）。
     いずれも**受方玉まわりの幾何と玉方持駒の在庫量**であり、単玉でもそのまま意味を持つ。
   - ただし `king_white_neighbors_black` や `total_black_kiki` は双玉では攻方玉の分を
     含んでいたので、**値の分布は単玉でずれる**（弱い分布シフト）。壊れはしないが
     最適とも限らないため、random beam との A/B を取る（§2-3）。
4. **合流点（gateway）解析 → 起点の再設計**
   得られた解群を `smoke_confluence` で解析し、全解が通る最深の局面（合流点）を求める。
   合流点を `--seed-sfen` に据えると、その先だけを **exact 全幅で数十秒で完全検証**でき、
   「この系列の上に N 枚は存在しない」を確定できる。40枚はこの方法で
   「39枚の壁は regime 内在」と確定させ、より深い合流点から探索し直して得られた。
5. **運用**: beam checkpoint/auto-resume、split（exact かつメモリ有界）、GCP spot。

### 2026-08-09 (2) 収束（詰上がり）の選抜 — max-step 25 の exact 全幅

**運用上の注意（この triage で判明）:**

- exact 全幅は step 25 でも**メモリを食い切る**。48 seed 並列で RSS 85GB に達したため、

  `--lance-knight-allow-start 8` に抵触して枝が全滅し
  `Error: No single-king smoke backward result` になる。
  → 収束を指定したいときは `--mate-square`（詰上がりの玉位置）で絞るか、
  列挙経路をそのまま使う。

### 2026-08-09 (6) どの制約が律速かの切り分け（decisive）

gateway からの exact オラクルは20分程度で終わるので、制約を1つずつ外して比較した:

| 構成 | 最大駒数 | 解の数 | 終了 |
|---|---:|---:|---|
| 44 regime（基準） | 27 @ 55 | 336 | completed |
| `--min-pawn-pct 30` に緩和 | 27 @ 55 | 384 | completed |
| `--goldish-priority` を外す | 27 @ 55 | 336 | completed |

### 2026-08-09 (11) 「壁」構造の検証 — どこに駒を詰め、玉をどこに入れないか

解の全局面から玉の段と1〜3段目の駒数を集計した（`smoke_dump_path` の出力を集計）:

| | 手数 | 玉が1-3段にいた局面 | 玉の段の分布 | 1-3段目の駒数（初形→中盤→詰上） |
|---|---|---|---|---|
| 本研究の33枚（単玉） | 78 | **6/78** | 7段:26, 9段:18, 8段:16 |  4 → 4 → 3 |
| 狼煙（双玉40枚） | 114 | **10/114** | 4〜7段に集中 | 5 → 4 → 3 |

- **1〜3段目（＝攻方の成可能エリア）はどちらもほぼ空**（40枚の狼煙ですら5枚）。
- **密集帯＝「壁」は4〜9段**にあり、**玉はその内側に閉じ込められて成可能エリアに上がれない**。
  狼煙の玉は 5六 で密集帯の中にいる。

この観点では、現在伸びている系列は詰上がりが 7一（1段目）で玉が最後に上まで来る形。
一方 run1 で見つけた**下段（1九など）で詰む系列**は玉が終始8〜9段に留まり、

### 2026-08-09 (12) `--white-king-min-rank` を実装（構造を制約として直接課す）

「壁で玉を成可能エリアから締め出す」構造は、これまで**評価関数（beam scorer）経由の
間接的な好み**でしか表現できていなかった。そこで frontier 局面に対する**硬い制約**として
実装した:

- `--white-king-min-rank N` … 受方玉が N 段目より上（＝1〜N-1段目）に居る局面を棄却。
  `--white-king-min-rank 4` で「玉は1〜3段目に一度も入れない」。
- 実装: `SearchConstraints::white_king_min_rank`（`Option<u8>`, serde は None で
  スキップ＝既存の checkpoint / condition_key と互換）、
  `satisfies_search_constraints` で判定。テスト
  `white_king_min_rank_keeps_king_out_of_promotion_zone` を追加。

これは探索空間を強く削るので、同じ beam 幅でより深くまで届く見込み。
ローカルで `--white-king-min-rank 4` 付きの全収束 sweep を実行中（canonical 2,369群）。

### 2026-08-09 (13) 「壁」の測定 — 33枚系列には壁が無かった

作者(ogiekako)の指摘: 長手数の逆算を支えるのは**攻方の成可能エリア(1〜3段目)が封鎖され、
玉がそこへ入れない構造**。成ると金以上の強い駒になり、典型的に余詰が出て一意性が壊れるので、
成りが起こり得ない状況を早い段階で作れると逆算が伸びる。詰み際に壁が壊れて玉が上段へ
入るのは煙詰として当然で、むしろそうなるべき。

解のパス上の全局面を解析して検証した（`scratch` の解析スクリプト）:

**(a) 攻方の着手** — 伸びる系列では攻方は成可能エリアに触れない:

| 作品 | 手数 | 攻方の成り | 攻方が1〜3段目へ動いた手 |
|---|---|---|---|
| 本研究 33枚 | 77 | **0回** | 72, 74, 76手目のみ |
| 本研究 27枚 | 55 | **0回** | 50, 52, 54手目のみ |
| 狼煙 40枚 | 113 | 2回 | 86, 106, 110, 112手目のみ |

**(b) 壁そのもの** — 3段目9マスのうち攻方が塞いでいる（駒が居る or 攻方の利きがある
＝玉が踏み込めない）マス数:

| | 初形付近 | 深部 (d=40〜84) |
|---|---|---|
| 狼煙（双玉40枚） | **9/9（完全封鎖）** | 7〜8/9 |
| 本研究の33枚（単玉） | 7/9 | **3/9** |

33で頭打ちになったのは構造的な必然と考えられる。

### 2026-08-09 (14) 壁を「存在要求」として実装

これまでの `--white-king-min-rank` は**禁止**でしかなく、壁を作らせる力はなかった。
壁の存在そのものを要求する制約を追加:

- `--rank3-seal-min N` / `--rank3-seal-from-step M`
  … step ≥ M で「3段目9マスのうち N マス以上を攻方が塞いでいる」ことを要求。
  実装は `rank3_sealed_count`（攻方各駒の `reachable_sub` を 3段目に射影 + 占有マス）。
- `--black-avoid-promotion-zone-from-step N`
  … step ≥ N で攻方が1〜3段目に触れる手（発着地が1〜3段目、または成る手）を禁止。
- いずれも詰み際（step < 閾値）には課さない。テスト3本追加。

**片方だけでは不十分**: 壁だけ課すと「壁は在るが玉が壁の上側(1〜3段目)に居る」形が出る。
`--rank3-seal-min` と `--white-king-min-rank` を**両方**課して初めて
「玉が壁の下に閉じ込められている」構造になる。
